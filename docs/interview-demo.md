## 面试前检查

- 若云端接口已接入，点击“检查云端模型”。只有基础模型、revision、adapter SHA256 与当前有效训练记录一致才开放新问题输入。检查会唤醒 GPU 并消耗计算额度；提前确认免费余额、现金支出上限为 0，再实际问一个新问题及追问。
- 若使用 Colab，确认会话连接、训练模型与 adapter 仍在内存，只运行第 8 节提问单元。免费 GPU 配额不足、会话重置或产物丢失时，这条现场提问路径不可用。面试前不临时重跑整个 notebook。
- 新Notebook要求训练前先挂载并验证Drive的独立run目录；导出后在Drive网页另行确认，再校验Mac下载的第二副本。第9节新增28题评估默认关闭，尚无真实GPU结果，不用流程测试替代。步骤见[备份与扩展评估](backup-and-evaluation.md)。

## 五分钟路线

1. **0:00–1:00，说明任务和资源约束。** “我用医院 HRP 问答完成了同基座前后评估、LoRA 训练和产物校验。数据共 33 条，25 条训练，8 条留出；4B 适应免费 T4 的资源预算。” 展示真实指标与分母 18/25、17/25。
2. **1:00–2:00，看完整定义。** 点击“看完整定义：VMI”，并排查看原始前后回答。说明更短并不自动代表更准确；本轮不能声称推理提速或总体质量改善。
3. **2:00–3:00，看指标局限和失败样本。** 点击“三单匹配”：微调回答使用“收货单”，字面规则未命中“入库单”；这说明指标需要人工业务复核，不能仅据同义词判断全篇正确。点击“HRP”：直接展示重复原文。也可选预算题，对照种子中的超预算阻断/特批规则，指出回答虽命中词却可能漏掉或解释错业务含义。
4. **3:00–4:00，新问题与追问。** 仅在模型检查通过时，输入“科室领用耗材需要哪些信息？”，再追问“这些信息分别有什么用？”。答案必须来自实际云端 adapter。输出触达 256 token 时显示上限提示；流中断或空回答会报错，不记为成功问答。也可在保留模型的 Colab 会话用 `interview_compare(...)` 现场生成基座/adapter 对比。
5. **4:00–5:00，展示可复核性与下一步。** 展开原始记录，指出同基座 revision、数据指纹、生成设置、环境与权重 SHA256。说明下一轮先扩充可靠数据、设置独立新题，并分别检查业务事实、遗漏、重复、截断与运行稳定性，不围绕这 8 题反复调参后宣称未见过的评估。

## 常见追问

**为什么从 14B 改成 4B？** 免费 T4 的显存与演示成本约束决定了可执行路线。本轮训练峰值已分配显存 8.84 GiB、可训练参数占比 0.47%。没有同条件 14B 对比，不能声称 4B 更强或是市场最优。

**为什么 LoRA，不做 Qwen3.5 的 4bit QLoRA？** 按 [Unsloth 官方指南](https://unsloth.ai/docs/models/qwen3.5/fine-tune) 采用非 4bit LoRA；该指南不推荐 Qwen3.5 的 4bit QLoRA。实际训练中 Unsloth 关闭了 FP16/BF16 混合精度标志，参数包含 FP16 和 FP32，原始记录保留实际状态。

**微调为什么下降？** 25 条训练与 8 道留出题都很小。关键词字面计数会受同义词、遗漏和生成长度影响；本轮同时存在重复与业务解释问题。现有结果不能单独确定根因，也未证明 adapter 更优，因此不将它验收为生产问答模型。

**RAG 与微调分别解决什么？** RAG 在回答时获取可更新的文档证据；LoRA 尝试调整领域表达与任务行为。本项目没有证明少量问答能可靠写入全部业务知识。集成 RAG 时仍需检查模型是否依据检索证据回答并正确引用。

**为什么网页不自己加载 4B？** 免费 Streamlit 只负责界面与证据展示，独立云端 GPU 承担推理；本机无需部署模型。候选 [Modal Starter](https://modal.com/pricing) 依赖实际账户免费余额；必须设置 [现金支出上限](https://modal.com/docs/guide/budgets)，额度不足就停止。冷启动、下载、空闲时间都会耗用计算额度，不能承诺永远免费或持续在线。

浏览器网络故障时打开事先下载的 JSON 与此指南，明确这是保存的实验记录。只有新问题、追问、实际 adapter 身份和业务质量均通过现场检查后，才写“云端在线推理已完成”。
